  - `HomePage`에서 `useLibraryStore.getState()`를 직접 호출하던 방식을 구독 상태인 `libraries` 변수를 직접 사용하도록 변경하여 React의 반응성 시스템에 부합하도록 수정했습니다.

## PR #54 피드백 및 수정 예정 사항 (2026-01-19)

PR #54 "feat: 시스템 개선 및 안정화 (동시성 제어, API 보안, UX 개선)"에 대한 리뷰 피드백 내용입니다.

### 1. 백엔드 및 시스템

- **에러 핸들링 및 안정성 강화**:
  - `Scanner`의 `UpdateScanStatus` 호출 시 에러가 발생하더라도 로그를 남기고 무시하여 전체 프로세스가 중단되지 않도록 보호가 필요합니다.
  - 고루틴(goroutine) 내부에서 채널 전송(`s.semaphore <- struct{}{}`) 전후에 `defer`를 이용한 안전한 자원 해제 로직을 재점검하여 채널 리크(leak)를 방지해야 합니다.
  - 데이터베이스 마이그레이션 시 SQLite 에러 메시지 문자열 비교 대신 에러 코드를 사용하거나, 쿼리 전 컬럼 존재 여부를 확인하는 방식으로 더 견고하게 수정해야 합니다.
- **로직 최적화**:
  - `Scanner`에서 `UpdateLastScanned`와 `UpdateScanStatus`가 중복 호출되는 지점을 정리하여 불필요한 DB 쓰기를 줄여야 합니다. (예: `UpdateLastScanned`가 'IDLE' 상태를 중복 설정함)

### 2. 프런트엔드

- **성능 및 코드 가독성**:
  - `LibrariesTab`의 폴링(Polling) `useEffect`에서 의존성 배열에 `fetchLibraries`가 포함되어 있어, 불필요한 재생성을 방지하기 위해 `useCallback` 처리가 선행되었는지 확인이 필요합니다.
  - `Library` 인터페이스 정의 시 `scan_status` 등의 필드를 열거형(Enum-like union)으로 관리하여 타입 안정성을 높이는 것을 권장합니다.
