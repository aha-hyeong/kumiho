# CI/CD 구성 계획

## 📋 프로젝트 현황

| 구분           | 기술 스택                             | 비고                         |
| :------------- | :------------------------------------ | :--------------------------- |
| **Backend**    | Go 1.24 + Fiber + SQLite (go-sqlite3) | CGO 필요 (C 컴파일러 의존성) |

## ✅ 결정된 사항

### 1. CI/CD 플랫폼

- **GitHub Actions** 사용 확정
- GitHub에서 호스팅 중이므로 가장 자연스러운 선택

### 2. 배포 타겟 플랫폼

- **Docker 이미지** + **Single Binary** (Linux/Windows/macOS 모두 지원)

### 3. CGO 크로스 컴파일 문제 해결

> Go + go-sqlite3 조합은 CGO 의존성 때문에 로컬에서 크로스 컴파일이 까다롭지만,  
> **GitHub Actions의 OS별 러너를 사용하면 문제없이 해결됩니다.**

| OS 러너          | 빌드 결과물           |
| :--------------- | :-------------------- |
| `ubuntu-latest`  | Linux용 바이너리 ✅   |
| `windows-latest` | Windows용 바이너리 ✅ |
| `macos-latest`   | macOS용 바이너리 ✅   |

→ 각 러너에서 **네이티브 빌드**하므로 크로스 컴파일 필요 없음!

### 4. 파이프라인 구성 범위

| 단계                   | 포함 여부 | 설명                                        |
| :--------------------- | :-------- | :------------------------------------------ |
| **Lint**               | [x]       | Go: `golangci-lint`, TS: `eslint`           |
| **Test**               | [ ]       | 현재 테스트 코드 없음 (추후 추가 시 활성화) |
| **Build**              | [x]       | Backend + Frontend 빌드 검증 (필수)         |
| **Docker Build**       | [x]       | 이미지 빌드 + 푸시 (필수)                   |
| **Release Automation** | [x]       | 태그 푸시 시 자동 릴리즈 생성               |

### 5. Docker 관련 설정

| 항목              | 결정 사항                                           |
| :---------------- | :-------------------------------------------------- |
| **베이스 이미지** | `golang:alpine` + `node:alpine` (멀티스테이지 빌드) |
| **레지스트리**    | Docker Hub (`ahahyeong/kumiho`)                     |
| **태그 전략**     | `latest` (main 머지 시) + `v0.1.0` (태그 생성 시)   |

### 6. 트리거 조건

| 트리거                | 동작                                                       |
| :-------------------- | :--------------------------------------------------------- |
| PR 생성/업데이트      | Lint + 빌드 검증                                           |
| `main` 브랜치 머지    | Docker 이미지 `latest` 태그로 푸시                         |
| 버전 태그 (`v*`) 생성 | 릴리즈 생성 + 바이너리 첨부 + Docker 이미지 버전 태그 푸시 |

### 7. 릴리즈 노트 관리 방법

1. **자동 생성**: 태그 생성 시 이전 태그 이후의 커밋/PR 목록이 자동으로 생성됨
2. **수동 편집**: GitHub Releases 페이지에서 "Edit" 버튼으로 하이라이트/요약 추가

```markdown
## ✨ v1.0.0 하이라이트

- 🔍 검색 기능 추가
- 📖 뷰어 성능 대폭 개선
- 🐛 다수 버그 수정

---

## What's Changed (자동 생성)

- feat: 검색 기능 추가 (#74)
- fix: 뷰어 진행률 동기화 버그 수정 (#65)
  ...
```

```
┌─────────────────────────────────────────────────────────────────┐
│                        GitHub Actions                           │
├─────────────────────────────────────────────────────────────────┤
│  1️⃣ PR / Push (모든 브랜치)                                    │
│     ├── Backend Lint (golangci-lint)                           │
│     ├── Frontend Lint (eslint)                                 │
│     ├── Backend Build (matrix: ubuntu, windows, macos)         │
│     └── Frontend Build                                         │
├─────────────────────────────────────────────────────────────────┤
│  2️⃣ Push to main                                               │
│     └── Docker Build + Push → Docker Hub (latest 태그)         │
├─────────────────────────────────────────────────────────────────┤
│  3️⃣ Tag (v*)                                                   │
│     ├── Multi-platform Binary Build (Linux/Windows/macOS)      │
│     ├── Docker Build + Push → Docker Hub (버전 태그)           │
│     └── GitHub Release 자동 생성 + 바이너리 첨부               │
└─────────────────────────────────────────────────────────────────┘
```

## 🔧 구현 계획

### 생성할 파일 목록

| 워크플로우 파일                 | 트리거           | 역할                                      |
| :------------------------------ | :--------------- | :---------------------------------------- |
| `.github/workflows/ci.yml`      | PR, Push         | Lint + Build 검증                         |
| `.github/workflows/docker.yml`  | main 브랜치 Push | Docker 이미지 빌드 및 푸시                |
| `.github/workflows/release.yml` | 태그 (`v*`)      | 릴리즈 생성 + 바이너리 + Docker 버전 태그 |
| **Dockerfile**                  | -                | 멀티스테이지 빌드용 Docker 설정           |
| **.golangci.yml**               | -                | Go Lint 설정 파일                         |

## 🚀 실무 배포 가이드

### 1. 배포 프로세스 (Workflow Flow)

1.  **개발 및 검증**: 하위 브랜치에서 작업 후 `dev` 브랜치로 머지하여 CI 통과 확인
2.  **최종 병합**: `dev` 브랜치를 `main`으로 머지 (자동으로 Docker `latest` 빌드 및 푸시 트리거)
3.  **릴리스 생성**: `main` 브랜치에 버전 태그(`v*`)를 생성하여 푸시 (자동으로 GitHub Release 및 버전별 Docker 이미지 생성 트리거)

### 2. 버전 릴리스 명령어

새로운 버전을 릴리스할 때(예: `v0.1.0`) 다음 명령어를 순서대로 실행합니다.

```bash
# 1. main 브랜치 최신화
git checkout main
git pull origin main

# 2. 버전 태그 생성 (앞에 'v' 접두사 필수)
git tag v0.1.0

# 3. 태그 원격 저장소 푸시
git push origin v0.1.0
```

> [!IMPORTANT]
>
> - 반드시 `main` 브랜치까지 머지가 완료된 상태에서 태그를 생성해야 합니다.
> - 태그 이름은 반드시 `v`로 시작해야 `release.yml` 워크플로우가 작동합니다.
